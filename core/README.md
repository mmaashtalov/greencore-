# GreenCore Core v0.1

Реальный программный контур GreenCore. Он отделён от демонстрационного симулятора урожайности и не зависит от конкретных моделей датчиков.

## Цель

Принимать телеметрию от виртуальных или физических устройств, проверять качество данных, принимать безопасные решения, формировать команды, тревоги и журнал событий.

## Базовая архитектура

1. Device Adapter — принимает данные от эмулятора, ручного ввода, ESP32 или стороннего контроллера.
2. Telemetry Ingest — проверяет формат, время, диапазоны и качество измерений.
3. State Store — хранит последнее подтверждённое состояние теплицы.
4. Rule Engine — рассчитывает требуемое состояние исполнительных устройств.
5. Safety Layer — ограничивает команды, контролирует таймауты и включает SAFE-режим.
6. Command Queue — выдаёт идемпотентные команды устройствам.
7. Event Log — записывает каждое измерение, решение, команду, подтверждение и тревогу.
8. Mobile UI — показывает состояние и позволяет владельцу менять режимы.

## Режимы

- AUTO — управление по правилам и достоверной телеметрии.
- MANUAL — временные команды владельца с обязательным сроком действия.
- SAFE — безопасное локальное состояние при неисправности, потере связи или недостоверных данных.
- OFFLINE — контроллер не связан с облаком, но продолжает локальные защитные алгоритмы.

## Принцип безопасности

Облако не должно напрямую переключать силовое реле. Оно формирует проверенную команду. Локальный контроллер повторно проверяет ограничения, применяет команду и возвращает подтверждение.

## Гипотетический пилот

Теплица `greenhouse-001`, зона `zone-001`:

- температура воздуха;
- относительная влажность воздуха;
- влажность субстрата;
- температура воды;
- уровень воды;
- насос;
- вентиляция;
- привод форточки.

Пока физического оборудования нет, источником данных служит отдельный device emulator. Его назначение — проверка настоящего API и логики, а не прогноз урожайности.

## Критерии готовности v0.1

- единые контракты устройств и телеметрии;
- валидация значений и времени;
- состояния ONLINE / STALE / FAULT / UNKNOWN;
- AUTO / MANUAL / SAFE;
- команды с TTL и подтверждением;
- журнал причин каждого решения;
- тестовые сценарии пропажи датчика, выхода за диапазон и потери связи.
