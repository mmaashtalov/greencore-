# GreenCore Core v0.1

Исполняемое, аппаратно-независимое ядро управления умной теплицей с HTTP API.

## Статус

- Физическое оборудование отсутствует и не считается протестированным.
- Пороговые значения в `rules/pilot-rules.json` являются тестовыми, а не агрономически подтверждёнными.
- Демонстрационный браузерный симулятор в `gh-pages` отделён от этого ядра.
- API пока хранит состояние только в памяти процесса.

## Реализовано

1. Приём и строгая проверка нормализованной телеметрии.
2. Контроль диапазонов, единиц, времени и качества данных.
3. Режимы `AUTO`, `MANUAL`, `SAFE`, `OFFLINE`.
4. Локальная автоматика при потере интернет-связи.
5. Safety interlock насоса по уровню воды.
6. Ограничение непрерывной работы насоса.
7. TTL, acknowledgement и идемпотентность команд.
8. Безопасное состояние при пропаже, устаревании или плохом качестве обязательной телеметрии.
9. Журнал событий, причин решений и тревог.
10. Детерминированный эмулятор устройств.
11. HTTP API без внешних зависимостей.
12. Автоматические unit- и integration-тесты.
13. GitHub Actions CI для Node.js 20 и 22.

## Запуск

Требование: Node.js 20+.

```bash
cd core
npm test
npm run demo
npm start
```

По умолчанию API слушает `0.0.0.0:3000`. Порт и адрес задаются переменными `PORT` и `HOST`.

Зависимости не требуются: используются только встроенные модули Node.js.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка доступности процесса |
| `GET` | `/state` | Полный снимок состояния ядра |
| `GET` | `/alerts` | Текущая история тревог |
| `GET` | `/events?limit=100` | Последние события |
| `POST` | `/telemetry` | Один sample или `{ "samples": [...] }` |
| `POST` | `/mode` | Установка режима |
| `POST` | `/connectivity` | Состояние внешней связи |
| `POST` | `/manual-commands` | Постановка ручной команды в очередь |
| `POST` | `/command-acks` | Подтверждение исполнения команды |
| `POST` | `/evaluate` | Выполнение одного цикла принятия решений |

Пример телеметрии:

```json
{
  "device_id": "soil_01",
  "metric": "soil_moisture",
  "value": 41.7,
  "unit": "%",
  "timestamp": "2026-07-28T10:00:00+03:00",
  "quality": "GOOD"
}
```

## Поток данных

```text
device emulator / будущий контроллер
→ POST /telemetry
→ validation
→ GreenCoreEngine
→ POST /evaluate
→ команда с TTL и idempotency key
→ локальная проверка устройства
→ POST /command-acks
→ журнал и тревоги
```

## Граница ответственности

`GreenCoreEngine` создаёт безопасное намерение управления. Реальный локальный контроллер обязан повторно проверить команду перед переключением силовой нагрузки. Облачный слой не должен напрямую и безусловно управлять реле.
