# GreenCore Core v0.5

Аппаратно-независимое ядро управления умной теплицей с автоматическим runtime loop, контрактом локального контроллера, безопасным восстановлением состояния и детерминированным цифровым двойником.

## Статус

- Физическое оборудование отсутствует и не считается протестированным.
- Пороговые значения в `rules/pilot-rules.json` тестовые, а не агрономически подтверждённые.
- Программный контур уже замкнут: `GreenCore → Controller Emulator → Digital Twin → telemetry → GreenCore`.
- Состояние ядра сохраняется в атомарно обновляемый JSON-файл. Это пилотная персистентность, не промышленная БД.

## Реализовано

- строгая проверка телеметрии, диапазонов, единиц, времени и качества;
- режимы `AUTO`, `MANUAL`, `SAFE`, `OFFLINE`;
- safety interlock насоса и лимит непрерывной работы;
- TTL, acknowledgement и идемпотентность команд;
- безопасное состояние при недостоверной или устаревшей телеметрии;
- атомарное сохранение, восстановление, rollback и quarantine повреждённого state;
- регистрация контроллеров, ownership устройств, heartbeat и offline timeout;
- контроллерные очереди, повторная доставка и ACK только от владельца устройства;
- отдельный Controller Emulator с локальной защитой и fault injection;
- автоматический неперекрывающийся цикл принятия решений;
- цифровой двойник воздуха, влажности, почвы, бака, оборудования и условного здоровья растений;
- ускоренное модельное время и воспроизводимые сценарии;
- unit-, integration-, recovery- и end-to-end тесты;
- GitHub Actions для Node.js 20 и 22.

## Запуск

Требование: Node.js 20+.

```bash
cd core
npm test
npm start
```

В другом процессе:

```bash
cd core
npm run emulator:controller
```

Сервер автоматически оценивает состояние. Ручной `POST /evaluate` сохранён для тестов и диагностики.

## Переменные сервера

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `HOST` | `0.0.0.0` | адрес API |
| `PORT` | `3000` | порт API |
| `STATE_FILE` | `data/state.json` | файл состояния |
| `AUTOMATION_ENABLED` | `true` | автоматический цикл; `false` отключает |
| `EVALUATION_INTERVAL_MS` | `5000` | интервал принятия решений |

## Переменные Controller Emulator

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `GREENCORE_URL` | `http://127.0.0.1:3000` | адрес GreenCore API |
| `CONTROLLER_ID` | `controller_primary` | идентификатор контроллера |
| `CONTROLLER_FIRMWARE` | `emulator-2.0.0` | виртуальная версия firmware |
| `DIGITAL_TWIN_PRESET` | `normal` | сценарий цифрового двойника |
| `SIMULATION_SPEED` | `1` | множитель модельного времени |

Доступные сценарии:

- `normal`;
- `heatwave`;
- `drought`;
- `leak`;
- `weak_ventilation`.

Пример ускоренного сценария жары:

```bash
DIGITAL_TWIN_PRESET=heatwave SIMULATION_SPEED=60 npm run emulator:controller
```

Одна реальная минута будет соответствовать одному модельному часу.

## HTTP API

### Система

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | доступность процесса |
| `GET` | `/state` | полный снимок runtime |
| `GET` | `/alerts` | тревоги |
| `GET` | `/events?limit=100` | журнал событий |
| `POST` | `/mode` | режим управления |
| `POST` | `/connectivity` | состояние внешней связи |
| `POST` | `/manual-commands` | ручной запрос с TTL |
| `POST` | `/evaluate` | диагностический цикл |

### Контроллер v1

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/controllers` | список и здоровье контроллеров |
| `POST` | `/controllers/register` | регистрация или обновление |
| `POST` | `/controllers/{id}/heartbeat` | heartbeat и диагностика |
| `GET` | `/controllers/{id}/configuration` | интервалы и разрешённые устройства |
| `GET` | `/controllers/{id}/commands` | незавершённые команды владельца |
| `POST` | `/controllers/{id}/telemetry` | телеметрия принадлежащих устройств |
| `POST` | `/controllers/{id}/command-acks` | контроллерный ACK |

Команда остаётся доступной до терминального ACK или истечения TTL. Повторная доставка безопасна благодаря постоянному `command_id`; эмулятор не повторяет физическое действие и возвращает сохранённый терминальный результат.

## Цифровой двойник

Модель связывает параметры между собой:

```text
время суток → наружная температура и солнце
солнце + наружный воздух → температура внутри
насос → влажность почвы и расход воды
вентилятор/форточка → температура и влажность воздуха
температура + солнце → испарение
неподходящие условия → модельный стресс растения
```

Модель не выдаётся за подтверждённый прогноз урожайности. Её задача — детерминированно проверять управление, отказоустойчивость и причинно-следственные реакции до подключения физического оборудования.

## Персистентность

Сохраняются режим, связь, телеметрия, состояния actuator, незавершённые команды, manual requests, контроллеры, ownership, heartbeat, idempotency keys, тревоги и события.

Запись выполняется через временный файл, `fsync` и атомарный `rename`. При ошибке сохранения мутация API или автоматического цикла откатывается. Повреждённый файл помещается в quarantine.

## Граница ответственности

`GreenCoreEngine` создаёт безопасное намерение. `GreenCoreRuntime` маршрутизирует его владельцу устройства. Локальный контроллер повторно проверяет команду перед исполнением. После появления ESP32 цифровой двойник заменяется физическими входами и выходами без изменения центральной архитектуры.
